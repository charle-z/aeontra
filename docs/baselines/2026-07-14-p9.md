## Delivered architecture

P9 adds server-anchored cross-repository memory without adding a resident service:

- strict Markdown plus YAML frontmatter is the only source of truth;
- `curated/` is owner-controlled and MCP-read-only;
- `working/` accepts only bounded agent writes with provenance and review dates;
- local Git has no remote and provides rollback history;
- `modernc.org/sqlite v1.53.0` provides in-process pure-Go SQLite FTS5;
- `.cache/brain.db` is disposable and rebuilds completely from Markdown;
- Brain uses a dedicated jail and is never exposed as a repository root;
- configured startup fails closed on overlap, symlinks, unsafe permissions, malformed
  notes, duplicate slugs, Git remotes, cache failures or reindex failures;
- no model, embedding service, vector daemon, queue, worker, database server, port,
  listener or new Coolify application is introduced.

`MCP_DEVBOX_BRAIN_ROOT` is optional. When unset, all five tools remain registered and
return the same safe disabled error. Production enablement requires the dedicated
persistent `/brain` mount and `MCP_DEVBOX_BRAIN_ROOT=/brain` on the existing app while
preserving `/repos` and `/state`.

## Trust, limits and safety controls

- one source file: 40 KiB maximum;
- Markdown body: 32 KiB maximum;
- indexed notes: 10,000 maximum;
- aggregate indexed source: 64 MiB maximum;
- query: 1–256 bytes;
- `top_k`: 20 maximum;
- excerpt: 480 bytes maximum per result;
- search response: 16 KiB maximum;
- backlinks: 128 maximum;
- context: 16 notes and 4 KiB maximum;
- agent notes require `agent:<name>`, provenance and bounded `review_by`;
- curated writes, owner impersonation, cross-author overwrite, traversal, separators,
  symlinks, arbitrary FTS syntax and secret-shaped writes fail closed;
- search, read and context are redacted before return;
- tool errors and observability do not expose Brain roots, private paths, note bodies,
  queries, slugs, tokens or raw errors.

## Smoke contract

`cmd/brain-smoke` is a read-only production verifier. Its integration test exercises a
real MCP HTTP handler with synthetic private data and proves output excludes bearer
credentials, Brain root, slug, title, provenance and body. The deployed command must
verify only:

- exact commit;
- `tool_count=67`;
- exact P9 catalog hash;
- Brain index readiness and schema;
- bounded note count;
- bounded context byte count.

After deployment it must run alongside `cmd/mcp-catalog-smoke`; no token, private note,
query, slug, path or context is printed. Production smoke remains pending at this
release-candidate checkpoint and must block the `p9` tag if it fails.

## Operations, backup and rollback

Authoritative data is `/brain/.git`, `/brain/.gitignore`, `/brain/curated` and
`/brain/working`; `.cache` may be deleted and rebuilt. Backup and restore preserve
UID/GID `10001:10001`, directory mode `0700`, file mode `0600`, and no Git remote.

Application rollback:

1. deploy the known-good `p8` commit/tag;
2. unset `MCP_DEVBOX_BRAIN_ROOT` for that binary;
3. keep the `/brain` volume intact;
4. do not delete or rewrite Brain data;
5. deploy P9 again only after fixing source, permissions or cache state and repeating
   all gates and smoke tests.

P9 preserves the exact **no resident service** invariant. The successful container
evidence proved **zero High/Critical** findings without an ignore, downgrade,
suppression or threshold reduction.

## Release decision

Staticcheck, Govulncheck, CodeQL, Dependency Review, Docker build, SBOM and the
zero-High/Critical Grype gate. Merge, volume/env configuration, deployment, exact
runtime identity, logs and both smoke commands remain mandatory before the annotated
`p9` tag. Console UI, OAuth migration, Edge, WSL/Parrot workcells and HTB integration
remain explicitly outside this branch.
