## P2 result

P2 split the former monolithic `internal/tools.Service` implementation into focused
capability services while retaining `Service` as the backwards-compatible composition
and configuration facade.

The resulting boundary is:

- `serviceCore` centrally owns policy, audit, root, command runner, redaction, jailed
  workdir resolution, and the shared action-plan store;
- `RepositoryCapability` owns repository context, filesystem reads/search, patch/create,
  structured memory, handoffs, and notes;
- `GitCapability` owns Git reads, commits, clone/fetch, fast-forward, publication,
  remotes, and owner-bound GitHub HTTPS authentication;
- `SourceCapability` owns configured GitHub repository lookup and planned creation;
- `PlatformCapability` owns Coolify compatibility, planned application/deployment,
  environment mutation, force deployment, and managed validation-runner creation;
- `ExecutionCapability` owns allowlisted commands, configured tests, sandbox access,
  private fixed-profile validation, and privileged profiles;
- `Service` exposes the existing fluent configuration API but delegates every mutation
  to the owning core or capability.

Compile-time assertions bind each capability to the exact catalog interfaces it must
implement. An AST guard rejects operational methods or direct dependency mutation on
the `Service` facade.

No public tool name, order, description, schema, version, alias, annotation, handler,
approval path, environment variable, tool count, or catalog hash changed.
