## Product contract

P12 introduces one opt-in profile only:

```text
linux-workcell
├── dev        (default mode)
└── htb-linux  (optional local context)
```

`htb-linux` is metadata of the same profile. It is not a second profile. Profile, mode, canonical path, HTB metadata, VPN interface, target, and LHOST remain owned by the local Edge registry. The VPS receives only opaque IDs, the bounded goal and timeout, runtime state, digests, and safe metrics.

The runtime identifies itself exactly as:

```text
TRUSTED LINUX WORKCELL
trusted_host_shared_network
```

The network posture is deliberately honest. This version shares the Parrot host network. It does not implement target isolation, egress filtering, nftables enforcement, or an overlay network.

## Architecture and trust boundary

The existing outbound P11.2 relay remains unchanged: VPS control plane, `mcp-edge`, `model-turn-driver`, Bubblewrap, provider, and pinned OpenCode remain separate processes. Only the local registry selects the workcell policy. Edge resolves the opaque workspace ID, performs local preflight, and re-resolves the complete contract before execution; path, profile, mode, or HTB metadata drift fails closed.

Repository files, model output, and VPS data cannot create a trusted registration or enlarge local authority. The running model receives no Edge identity, device key, browser profile, SSH key, host home, Windows mount, private control-plane socket, or unrelated workspace.

## Sandbox regression boundary

The P11.2 `sandbox` remains:

- networkless;
- without Docker or Podman sockets;
- Bubblewrap fail-closed;
- minimal filesystem;
- explicit rejection of `--share-net`;
- no direct-execution fallback.

`linux-workcell` uses a separate validator. It derives from the P11.2 mount baseline, adds explicit `--share-net`, workspace-local package prefixes, optional root-owned read-only wordlists, and an optional verified rootless container socket. The trusted profile cannot silently change sandbox behavior.

## Filesystem

Registered workspaces must be canonical Linux directories below administrator-approved roots, normally:

```text
/home/charles/workspaces/<PROJECT>
/home/charles/htb-machines/<MACHINE>
```

The registry rejects roots themselves, `/mnt/c`, `/mnt/d`, symlinks, unauthorized roots, duplicate/other workspaces, and paths outside the selected workspace. Bubblewrap exposes the selected workspace read/write, a private runtime read/write, the pinned provider and OpenCode executable read-only, required system runtime paths read-only, `/proc`, `/dev`, and ephemeral `/tmp`.

Optional `/usr/share/seclists` and `/usr/share/wordlists` mounts are added only when each path:

- exists;
- is a real directory;
- contains no symlink component;
- is owned by root;
- is not writable by group or others;
- remains inside `/usr/share`;
- is mounted read-only.

Absence is valid and does not block execution. No other `/usr/share` content is exposed.

## User dependencies and development mode

`dev` is the default. It permits repository reads and edits, tests, builds, child processes, temporary services, compilers, downloads into the workspace, user-scoped Python environments, private pipx, workspace npm/pnpm, private Go installs, private Cargo/Rustup state, and packages inside rootless containers. It grants no general sudo and performs no silent host `apt` installation.

Persistent workspace-local prefixes live below `.mcp-devbox/tools`, `.mcp-devbox/cache`, and `.mcp-devbox/runtime`. The maximum lease remains 3600 seconds.

## Tool inventory

The local inventory reports only tool name, availability, sanitized version token, and capability. It executes no shell, bounds version commands by time and output, and never prints executable paths. The inventory is available through the local Edge CLI and stored locally for the runtime. It is not an MCP tool and is not sent to the VPS as host-path data.

## Rootless Docker or Podman

P12 accepts an engine endpoint only when:

- Edge is non-root;
- the CLI resolves from an allowlisted system or managed tool root;
- the Unix socket is below `/run/user/<edge_uid>`;
- parent and socket are not symlinks;
- the socket is owned by the Edge user;
- parent/socket permissions are private.

It expressly rejects `/var/run/docker.sock`, `/run/docker.sock`, rootful sockets, Docker Desktop sockets, and unexpected writable host binds. The selected workspace remains the only project bind.

The runtime receives a fixed private socket target plus the exact label `mcp.devbox.runtime=<runtime_id>`. Pods, containers, networks, and volumes are listed and removed only through that label. Podman pods are removed before their containers, and cancellation kills the complete local process group rather than only its leader. The workflow trap also stops the user-owned API process group, removes its temporary socket, restores any temporarily restricted rootful socket permissions, and verifies both cycle labels are empty. Engine output and resource identifiers are bounded and validated. Cleanup failure is recorded and fails the local runtime rather than reporting success.

## HTB Linux context

`htb-linux` requires local typed metadata and a workspace below the HTB root. Preflight validates:

- configured interface exists;
- interface has IPv4;
- target is one IPv4 address, never CIDR;
- `ip route get <target>` uses the configured interface;
- LHOST is derived from that interface.

The VPN is started and controlled by the human outside Bubblewrap. P12 does not claim that shared host networking is technically restricted to the target.

The versioned `profiles/htb-linux-v1.md` template retains authorization, user/root objectives, bounded recon, anti-loop behavior, guided enumeration, exploitation, lateral movement, privilege escalation, flag handling, known-chain tracking, newly-published-machine behavior, cleanup, and response format. It forbids writeups, flags, machine solutions, spoilers, and reused external secrets.

## Local memory and resume

The operational memory contract is:

- `.mcp-devbox/instructions.md` — rendered, immutable per runtime;
- `.mcp-devbox/current-state.md` — bounded writable checkpoint.

`current-state.md` is read first on resume, but actual filesystem, process, service, test, network, and access state must be revalidated. It is updated after material progress and before cancellation, timeout, completion, or failure. Terminal checkpoints record state, stopped process group, cleanup status, and local checkpoint path.

P12 does not add Goal Runtime, handoff JSON, commands JSONL, another database, a scheduler, 24-hour jobs, advanced orchestration, or public onboarding.

## Cancellation and cleanup

OpenCode remains inside Bubblewrap with `--die-with-parent` and `--new-session`. The runtime process group is terminated on cancellation or timeout. Rootless client commands use the same whole-process-group cancellation rule with a bounded wait, so a timed-out `podman wait` cannot leave a child process running. Rootless cleanup is independently time-bounded and registered before resource creation. Local STOP, device revocation, and remote cancellation remain separate stop mechanisms.

## Controlled fixture evidence

Unit and integration fixtures cover registry migration, default dev mode, typed HTB metadata, target and route failures, rendered instructions, durable state, resume, sandbox regression, shared-network selection, exact mounts, tool inventory, rootless endpoint validation, runtime-labelled cleanup, and terminal checkpoints.

CI must use controlled fixtures only. It must not access a public HTB machine. Device-dependent PostgreSQL, Chromium, rootless-engine, distributed OpenCode, restart/resume, cancellation, and HTB fixture gates execute in GitHub/approved host jobs; the real Parrot machine remains untouched until the human setup phase.

The blocking workflow `.github/workflows/trusted-linux-workcell-e2e.yml` adds two actual-process jobs:

- `Trusted host and HTB fixture` runs Bubblewrap with the trusted host network, verifies workspace/runtime writes, root-owned read-only wordlists, hidden host/Windows/rootful paths, process-group cancellation, and a controlled local HTB HTTP fixture with preflight, recon, exploitation, fixture user/root flags, cleanup, state, and resume;
- `Rootless Podman, PostgreSQL and Chromium` derives two distinct runtime IDs from the GitHub run, makes any host rootful socket inaccessible to the test user, starts a user-owned Podman API below `/run/user/<uid>`, and executes two consecutive clean cycles. Each cycle performs a real image build, the workspace as the sole project bind, an explicitly labelled pod, Podman Compose with condition-based readiness and `down`, PostgreSQL healthcheck plus query, headless Chromium smoke, process-group cancellation, and exact-label cleanup of pods, containers, networks, and volumes. The job then restarts the API, proves neither cycle survives, and a trap always removes resources, processes, and the temporary socket.

The existing `.github/workflows/opencode-e2e.yml` remains the blocking evidence for the four-process distributed OpenCode relay, pinned OpenCode 1.18.1, real Bubblewrap host isolation, unchanged networkless sandbox behavior, restart/resume, and zero duplicate turns.

P12 reports contain only booleans and bounded identifiers. The workflow asserts that fixture flags, authorization material, cookies, and private keys are absent. On a rootless failure, raw test and daemon output are not uploaded: a dedicated bounded allowlist redactor emits only test-state lines and stable failure categories, and the diagnostic artifact exists only for failed runs while preserving the original exit code.

## Residual risks

- Host-shared networking allows general outbound traffic and callbacks.
- No target-only network enforcement exists.
- A rootless engine still grants broad authority inside the Edge user's namespace.
- Cleanup can safely remove only resources carrying the exact runtime label.
- The model can modify all files inside the selected workspace, including local evidence and state.
- Host/systemd and engine-level CPU, memory, disk, and process ceilings remain part of human installation.
- The no-writeup rule is an operational contract, not an Internet content filter.
- Real Parrot behavior remains validation pending until the owner performs the documented setup and smokes.
