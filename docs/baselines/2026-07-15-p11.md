## Persistence, quotas, and retention

- Telemetry SQLite: 128 MiB page target; hourly buckets for 7 days and daily buckets
  for 90 days; no prompts, params, results, identities, paths, tokens, or cookies.
- Observability: 4 x 16 MiB fixed segments.
- Audit: 4 x 32 MiB fixed segments; the prior audit is not deleted automatically.
- Result store: 256 MiB logical quota; successes expire after 24 hours and failures
  after 7 days; reads are opaque-ref-only and capped at 16 KiB.
- Edge Core SQLite: 8192-page maximum. Local Edge journal: 4096-page maximum.
- Output is centrally redacted before result, audit, journal, or task persistence.

## Edge security model

- `/edge/v1/pair` exchanges a 192-bit, hashed, one-use pairing code valid for no more
  than ten minutes for a client-generated Ed25519 public key.
- Every later `/edge/v1/*` request signs device, timestamp, nonce, method, exact path,
  and the SHA-256 body digest. A two-minute clock window plus persistent ten-minute
  nonces provides anti-replay protection.
- Revocation causes later authentication and heartbeat to fail closed.
- Structured `validate` tasks use bounded leases, exact lease IDs, per-device
  idempotency keys, heartbeat cancellation and terminal-result replay checks.
- The WSL client journals `started` before execution and `completed` before delivery;
  an interrupted start requires manual reconciliation instead of double execution.
- Bubblewrap uses `--unshare-all`, a single writable workspace, read-only runtime
  mounts, private `/tmp`, no network and no host home or private Edge state.
- The systemd unit runs as `mcpedge`, applies `NoNewPrivileges`, a strict filesystem,
  private devices/tmp, an empty capability set, and writable access only to Edge state
  and the dedicated Linux workspace root.

Explicit exclusions: **No remote shell**, **No Docker socket**, **No Windows mounts**,
**No remote sudo**, no terminal web, no Parrot, HTB, Burp, registry egress, arbitrary
argv, project selector expansion, or automated WSL installation/pairing.

## Rollback

1. Do not create a pairing code before the exact candidate is merged and deployed.
2. If deployment fails, redeploy the known-good `p8.1` commit/tag and preserve
   `/state`, `/repos`, and `/brain` unchanged.
3. The previous binary ignores candidate-only Edge state and continues serving the
   historical 67-tool contract.
4. If a device was paired only after a later approved deployment, revoke it before
   rollback and stop the local service; do not delete audit or Edge state until review.
5. Repeat all gates and exact catalog/Brain/console smokes before attempting another
   deployment.
