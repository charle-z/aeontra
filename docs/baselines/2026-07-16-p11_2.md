## Architecture proved

```text
GitHub runner host
├── MCP test server and authoritative model-turn store
├── mcp-edge process and private journal
├── model-turn-driver process and Unix socket
└── Bubblewrap
    └── OpenCode 1.18.1 with the local external-driver provider
```

The server, Edge, driver, and OpenCode have distinct PIDs. Only OpenCode enters
Bubblewrap. The Docker job proves the distributed signed relay without elevated
container permissions; the Ubuntu 22.04 host job proves the real sandbox used by
the production design.

The three evidence modes are deliberately separate:

- `relay_container_e2e`: signed HTTP relay, lease/create/wait/response,
  request references, restart/resume, reports, and no duplicate consumption;
- `bubblewrap_host_e2e`: incremental namespace/mount preflight and isolation;
- `combined_opencode_sandbox_e2e`: complete server → Edge → driver → Bubblewrap →
  OpenCode path on the host runner.

There is no fallback that executes OpenCode directly when Bubblewrap fails.

## Parrot WSL operations

`docs/install-opencode-edge-parrot.md` documents the human-controlled Parrot WSL2
installation, systemd, dedicated `mcpedge` user, minimal groups, `0700`/`0600`
permissions, pinned OpenCode integrity, provider installation, workspace registry,

rollback, and uninstall. Its preflight fails before pairing when Bubblewrap cannot
create the required namespaces and mounts.

It does not install a Docker socket, arbitrary sudo, a remote apt mechanism, VPN,
HTB/THM, or the Build Workcell.

## Residual risks and limits

- Parrot WSL2 has not been installed or paired in this phase. Its kernel, systemd,
  and user-namespace policy must pass the documented local preflight first.
- Ubuntu 22.04 is the authoritative CI host because Ubuntu 24.04 runner policy may
  block unprivileged user namespaces through AppArmor. No global runner security
  setting is disabled.
- `mcp-edge` and `model-turn-driver` are trusted host processes; the untrusted
  OpenCode process alone is inside Bubblewrap.
- The sandbox intentionally has no external network. Networked project workflows
  require a separately reviewed policy rather than a fallback.
- The A/B/C timings are deterministic test-harness observations, not production
  service-level objectives and not model latency.
- No merge, deployment, pairing, real Parrot installation, tag, Coolify change,
  frontend expansion, Goal Runtime, Build Workcell, or HTB/THM/VPN work is included.

## Rollback

Because this phase is not deployed, rollback is branch-only: do not merge or pair
the device, and return to the reviewed base or prior branch commit. After any later
approved deployment, revoke the device before removing local identity, stop the
systemd service, preserve audit/state for review, and restore the last known-good
binary and pinned package set. Never bypass Bubblewrap to recover availability.
