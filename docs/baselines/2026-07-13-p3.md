## P3 result

P3 reduced `cmd/mcp-devbox/main.go` to a true composition root containing only one
import and one call to `app.Main()`. Process orchestration moved into focused modules
under `internal/app` without changing commands, flags, environment-variable names,
authentication, security policy, tool registration or runtime behavior.

The resulting boundary is:

- `run.go` owns command dispatch, usage output and stable exit codes;
- `env.go` is the single source for deployed `MCP_DEVBOX_*`, `COOLIFY_*`, `GITHUB_*`
  and `SOURCE_COMMIT` environment-variable literals;
- `oauth.go` constructs the optional OAuth provider from the existing variables;
- `serve_config.go` parses flags and environment fallbacks into immutable validated
  options through `parseServeOptions`;
- `runtime.go` builds policy, audit, `tools.Service`, optional integrations and the MCP
  server through `appRuntime`;
- `grant_admin.go` owns the loopback-only local approval channel and bounded shutdown;
- `transport.go` owns stdio/HTTP selection, address normalization, bearer/OAuth
  resolution, fail-closed HTTP authentication and signal-aware draining;
- `serve.go` is only the lifecycle coordinator;
- `grant.go` remains the local grant client.

AST regression tests protect both boundaries: the executable must remain a single
`app.Main()` delegation, and deployed environment-variable literals must remain
centralized in `env.go`.

No public tool name, order, schema, handler, alias, annotation, approval path, command,
flag, environment-variable name or meaning, transport contract, tool count, or catalog
hash changed.
