## Frontend architecture and UX

The design source remains `docs/console-2.0/design-neo-bios.md` and
`docs/console-2.0/mockup.html`. The mockup is a visual specification, not production
source. The maintainable frontend lives under `web/console` and uses React,
TypeScript and Vite. Vite emits fixed same-origin `index.html`, `app.css` and
`app.js` assets that Go embeds under `internal/console/assets`; production contains no
Node server or frontend runtime dependency.

The console implements the single blue VGA BIOS theme with `#0000A8`, a 16-color VGA
palette, square geometry, monospaced typography, tabbed firmware screens, list plus
Item Specific Help layout, function-key bar, keyboard/touch/mouse navigation and
`prefers-reduced-motion`. CSS gradients, rounded-design-system components, inline
scripts, inline event handlers, third-party assets, analytics, browser storage,
service workers and WebSockets are absent.

## Authentication migration

The migration was deliberately completed in two tested steps:

1. `/console/auth/start` creates bounded one-use OAuth state and PKCE S256 material,
   stores only the SHA-256 state digest, and redirects to the existing
   `/oauth/authorize` owner-passphrase page. The passphrase is accepted only there.
   `/console/auth/callback` validates exact state, PKCE, client, callback, audience,
   scope and single-use code server-side, then creates an opaque console session.
2. Query-string authentication was removed only after the console OAuth flow passed.
   `?key=<MCP_DEVBOX_TOKEN>` now returns HTTP 401 even when the value is correct.
   `Authorization: Bearer <MCP_DEVBOX_TOKEN>` remains a recovery mechanism and the
   recovery form submits the bearer only in an HTTPS request body.

The final browser cookie is opaque, `Secure`, `HttpOnly`, `SameSite=Strict`, scoped to
`/console`, and stored server-side only as a digest. Access tokens, refresh tokens,
passphrases, codes, state values and PKCE verifiers do not reach JavaScript or final
URLs. Existing persisted OAuth public clients and rotating refresh tokens continue to
survive restart through `/state`.

## Durable task journal and live state

`MCP_DEVBOX_TASK_ROOT` is optional outside the image and defaults to `/state/tasks` in
the production image. The journal is bounded, file-based and contains only
server-generated fields:

```text
task_id, operation, summary, state, heartbeat, controller
```

Allowed states are exactly:

```text
requested, planned, awaiting_approval, executing, observing, validating,
completed, failed, cancelled, disconnected
```

The fixed summary is derived only from the public operation name. Prompts, reasoning,
parameters, results, repositories, paths, commands, targets, identities, IPs, tokens
and raw errors are never stored. Active records whose heartbeat expires are rendered
`disconnected`; the durable record is not rewritten to fake a transition. There is no
background worker or autonomous task loop.

Authenticated `/console/tasks` returns a closed snapshot schema. Authenticated
`/console/events` uses Server-Sent Events with snapshot, task and heartbeat frames;
SSE is best-effort and polling remains the durable fallback. WebSockets are not used.

## Safe data contract

Authenticated `/console/data` has one exact nested allowlist and returns only:

- real container CPU count, RAM, disk and Linux load averages, with an explicit
  availability flag;
- authenticated MCP request and response bytes counted in-process;
- declared token estimate `bytes / 4 (estimate)`; it is not provider billing;
- aggregate P7 route request/4xx/5xx/P95 counters from normalized events only;
- security posture: OAuth, bearer recovery, rejected query auth, strict cookie,
  presentation-only authority and absent free shell;
- Brain readiness, schema, note/source/link counts and index timestamp;
- a bounded real Brain link graph using opaque ordinal IDs (`n0001`, etc.), trust and
  degree only. Slugs, titles, bodies, authors and provenance remain private;
- Edge state `not_paired` until P11.

Schema tests enumerate every allowed key. Any added field fails the build.
