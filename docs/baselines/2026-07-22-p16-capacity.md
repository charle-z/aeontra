# P16 VPS capacity baseline — 2026-07-22

Status: **measured planning baseline**, not final worker calibration.

## Purpose

Measure the current production VPS at rest and during one real MCP Devbox Coolify
redeploy without cache so P16 resource defaults are based on observed behavior rather
than provider marketing or assumed hardware generation.

The raw operator captures were:

```text
vps-capacity-idle-20260722-173642.tar.gz
vps-capacity-build-20260722-183821.tar.gz
```

The captures contain `mpstat`, `iostat`, `pidstat`, `sar`, `/proc/pressure`, `free`,
Docker snapshots, and safe host metadata. Raw capture archives are external evidence;
this repository stores the bounded interpretation, not the complete host telemetry.

## Real-build storage behavior

The real deploy did not show sustained block-device saturation. Observed samples
included bursts, but the virtual `vda` device generally remained well below full
utilization. The workload is therefore not a reason to impose a hard throughput/IOPS
ceiling in the initial policy. Use a lower I/O weight first and add hard limits only if
isolated worker telemetry proves interference.

Operator `fio` probes, executed after the deploy, reported:

```text
sequential write, 1 MiB blocks, depth 4:
  1657 MiB/s, 1656 IOPS, approximately 0.95 ms average total latency

sequential read, 1 MiB blocks, depth 4:
  7529 MiB/s reported

random read, 4 KiB blocks, depth 16, 20s:
  17.6k IOPS, 68.7 MiB/s, approximately 0.91 ms average total latency
```

The sequential-read result showed no corresponding `vda` operations in `fio` disk
statistics and must not be treated as guaranteed physical-device throughput; a host or
storage-layer cache likely influenced it. The random-read and write results are enough
to show that disk was not the primary problem in this measured build.

## Initial P16 policy candidates

These values are inputs to the isolated worker spike, not final production truth:

```text
vps.build max active: 1
CPU default: 650 millicores
CPU calibration: 500 / 650 / 800 millicores
MemoryHigh: 1280 MiB
MemoryMax: 1792 MiB
SwapMax: 256 MiB
PIDs max: 512
I/O weight: 25
```

Rationale:

- idle p95 consumes approximately 0.82 vCPU-equivalent of the two-vCPU host;
- a 0.65-vCPU worker budget leaves capacity for the control plane, Coolify, proxy,
  databases, applications, and concurrent non-build chat operations;
- the hard maximum remains below one complete CPU until the controlled 50/65/80 test
  proves a better point;
- CPU quota is expected to lengthen builds, which is acceptable only if control-plane
  health and fairness improve.
