## Delivered behavior

P8 embeds a dependency-free dark console in the existing Go HTTP application:

- `GET /console` renders a minimal login page or the authenticated console;
- `POST /console/login` validates the existing static MCP token in constant time;
- existing bearer/OAuth authorization can bootstrap a browser session;
- `POST /console/logout` revokes the current session;
- `GET /console/status` returns an exact public runtime schema;
- CSS and JavaScript are embedded same-origin assets.

The console is presentation-only. It cannot execute tools, approve plans, enumerate
repositories, read source, prompts, params, results, targets, audit, observability
history, logs, credentials, identities, infrastructure inventories, or configuration.

Sessions use 32 random bytes; only SHA-256 digests are stored. They expire after eight
hours, are capped at 128, are revoked by logout/expiry/restart, and use cookies scoped
to `/console` with `HttpOnly`, `SameSite=Strict`, and `Secure` on production HTTPS.

Every console response carries restrictive CSP, frame, referrer, content-type,
permissions, cache, and cross-origin headers. Assets use no CDN, remote font,
analytics, service worker, browser storage, WebSocket, `innerHTML`, or JavaScript-
readable cookie.

## External audit nits

A read-only external review requested two explicit corrections:

1. login protocol-error responses previously called `loginCSP("invalid")` and
   `loginCSP("oversize")`, creating deterministic pseudo-nonces. Step 1 now uses a
   separate nonce-free `errorCSP()` with no `style-src` for unsupported media type and
   oversized-body responses. Focused tests reject `style-src` and `nonce-` in those
   error CSPs.
2. `GET /console` with already-valid bearer/OAuth authorization intentionally creates
   session state. The threat model now records this accepted exception: the existing
   credential already has authority, a fresh opaque session is minted, the request
   redirects to the clean `/console` URL, and no additional control-plane authority is
   granted.

No suppression, threshold reduction, allowlist, or workflow weakening was used.
